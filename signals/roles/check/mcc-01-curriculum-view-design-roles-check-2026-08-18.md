# Roles Check: MCC-01 Curriculum View Design

Artifact type: two no-new-anchor Factor Table view specifications with
established-source research. Domain signals include mathematical optimization,
decision handoff, human-centred design, usability/accessibility, participant
evidence, privacy, mappings, procedures, and reference architecture.

## Role selection

Experimental Methodologist checks frozen evidence and tests; Reference
Lexicographer checks sense/owner boundaries; Concept & Taxonomy Boundary Editor
checks enumeration; Reference Architecture Editor checks view authority;
Evidence & Claims Editor checks claims; Domain Source Reviewer checks
optimization and human-factors sources; Research Integrity & Provenance checks
custody; Mapping Integrity Auditor checks direction/loss; Reference
Practitioner checks lookup use; Product Owner checks value and cost.

## Synthesis

Roles reviewed: 10

P1 blockers: 0 | P2 issues: 0 | P3 notes: 30

Verdict: APPROVED

Top finding: both candidates earn no-new-anchor view designs, but only if the
optimization-to-decision and prototype-to-production handoffs remain explicit.

Cross-role consensus: the views add value through boundary preservation, not
through catalogs of solvers, design methods, tools, or course terminology.

## Amendments applied

1. Added explicit enumeration stops for optimization families/algorithms and
   UX methods/tools so neither view can become a domain catalog.
2. Added production, privacy, accessibility, conformance, authority, and reader-
   evidence boundaries to the prototype procedure.
3. Added optimality support, tolerances, status, sensitivity, mapping loss, and
   decision handoff to prevent solver output from becoming automatic advice.
