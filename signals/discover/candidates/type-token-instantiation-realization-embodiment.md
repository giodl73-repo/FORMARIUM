# Type, Token, Instantiation, Realization, and Embodiment

Status: noncanonical candidate entry draft; descriptive, not diagnostic

## Orientation

A type is a repeatable kind, universal, or general, individuated by a stated
criterion. A token is a particular that instantiates a type under a stated
instantiation criterion. Realization is the relation by which a concrete or
lower-level arrangement realizes a functional or higher-level kind, and the
same kind may be realized by many distinct arrangements. A disposition is
displayed under its manifestation conditions and remains present when it is not
displayed. Embodiment is the relation by which a body or material bearer
sustains a capacity or content, where the bearer constitutes rather than merely
houses what it carries.

This entry owns the abstract-to-concrete relation. It does not own
classification of identified entities, representation and modelling, perceptual
appearance, figures projected to an audience, staged change of a subject, or
template reuse.

"Manifestation" is admitted only in the dispositional sense. The following are
excluded by name and routed: the bibliographic manifestation in the work,
expression, manifestation, and item chain, which belongs to an external
standard and to a mapping view; the clinical symptom as evidence of a
condition; religious theophany; public demonstration; and popular "manifesting".
"Embodiment" is bounded to the bearer and constitution question and commits to
no position on mind and body.

"Type" is likewise guarded. The language or runtime sense — the set of values,
interpretation rules, operations, and validity constraints that apply under a
language model — belongs to the canonical Software Type, Value, and Function
entry, together with `value` and `function`. That sense is excluded here by
name, which is why the repeatable-kind sense is labelled `general-type`. A
software value is not a token of this family, and a token of this family is not
a software value.

## Sense table

| Sense | Governing question | Role |
|---|---|---|
| `general-type` | Which repeatable kind, universal, or general is at issue, and by which individuation criterion? | repeatable kind |
| `token-instantiation` | Which particular is an instance of which type, and under which instantiation criterion? | particular case relation |
| `realization` | Which concrete or lower-level arrangement realizes which functional or higher-level kind, and is the realization multiple? | level-crossing relation |
| `disposition-manifestation` | Which stimulus condition displays which disposition, and is the disposition present when unmanifested? | latent-to-displayed relation |
| `embodiment` | Which body or material bearer sustains this capacity or content, and does it constitute rather than merely house it? | bearer relation |

## Decisive distinctions

| Pair | Shared feature | Decisive distinction |
|---|---|---|
| Type vs. class | both group particulars | a repeatable kind that particulars instantiate vs. an assigned class in a classification scheme |
| General type vs. software type | both constrain what counts as an instance | a repeatable kind individuated by a stated criterion, with instantiation evidence vs. a language or runtime classification of values fixing interpretation rules, valid operations, and evaluation, owned by the software entry |
| Token vs. entity identity | both concern a particular | this particular as an instance of a type vs. continuity criteria for the entity itself |
| Token vs. version | both are particular cases | an instance of a type vs. a successive form of the same identified item |
| Token vs. copy | both are particulars of one type | any instance under the instantiation criterion vs. one produced from another instance |
| Instantiation vs. classification | both relate particular and general | the particular is a case of the type under a criterion vs. the entity is assigned to a class by a scheme |
| Instantiation vs. template instantiation | both produce a case | a particular instantiating a type vs. a prototype filled through declared slots |
| Realization vs. instantiation | both relate levels or generalities | an arrangement realizing a functional kind, possibly in many ways vs. a particular being a case of a type |
| Realization vs. representation | both connect two things | one thing making another actual at a level vs. one thing standing for another for a purpose |
| Realization vs. implementation | both make something actual | the general level-crossing relation vs. a built artifact satisfying a specification |
| Multiple realization vs. equivalence | both allow substitution | different arrangements realizing one kind vs. sameness under a declared criterion |
| Disposition vs. its manifestation | both concern the same power | the standing property, present when undisplayed vs. the display under the stimulus condition |
| Manifestation vs. symptom | both are observable displays | a display of a disposition under stated conditions vs. a clinical sign taken as evidence of a condition |
| Dispositional vs. bibliographic manifestation | homonym only | display of a power vs. a physical or digital embodiment of an expression of a work |
| Embodiment vs. containment | both involve a bearer | the bearer constitutes the capacity or content vs. the bearer merely holds it |
| Embodiment vs. realization | both are level-crossing | a body or material bearer sustaining a capacity vs. any arrangement realizing a kind |
| Embodiment vs. avatar | both link an agent to a figure | a bearer sustaining capacities vs. a controlled figure presented to an audience |
| Embodiment vs. appearance | both are encountered concretely | the bearer relation vs. how something seems to a perceiver |
| Becoming concrete vs. state change | both involve time | an abstract or latent item having a concrete case vs. a subject moving between guarded states |

## Dependencies and stopping boundary

- The abstract, general, functional, or latent item and the particular are both
  identified before a relation is claimed.
- Every instantiation claim states its criterion; an implicit criterion is a
  defect, not a shortcut.
- Realization records the levels involved and whether the realization is
  multiple.
- A disposition is not eliminated by non-display; non-display is recorded as a
  condition, not as absence.
- Embodiment states whether the bearer constitutes or merely contains, and does
  not settle mind-body questions.
- A mandatory manifestation guard runs before any use of the word; the
  bibliographic chain routes to an external standard through a mapping view.
- Clinical inference from a sign to a condition is out of scope and routes to
  observation and evidence custody.
- Classification, versioning, representation, appearance, projected identity,
  staged change, and template reuse retain their existing or candidate owners.
- The language or runtime senses of type, value, and function retain the
  canonical software entry as their owner; `general-type` never covers them.
- Lexeme and word-form, as the language-specific case of a general kind and its
  particular realizations, retain the morpheme and word-formation candidate as
  their owner; this entry supplies only the general relation.
- Competing accounts of types, realization, and embodiment remain visible.

This entry stops before cataloguing rules, diagnostic criteria, religious
doctrine, political demonstration, the resolution of the universals debate,
mind-body positions, and specific implementations of any specification.

## Selection procedure

1. Identify the general item and the particular, and state the individuation
   criterion for each.
2. Run the manifestation sense check and the type sense check, and name the
   excluded senses before proceeding; a language or runtime type, value, or
   function routes to the software entry at this step.
3. State whether the question concerns type, instantiation, realization,
   disposition manifestation, or embodiment.
4. For instantiation, record the criterion and the evidence that this
   particular satisfies it.
5. For realization, name the realizing arrangement, the realized kind, the
   levels involved, and whether other arrangements realize the same kind.
6. For disposition manifestation, record the stimulus condition, the display or
   its absence, and the fact that the disposition persists undisplayed.
7. For embodiment, name the bearer and state whether it constitutes or contains
   the capacity or content.
8. Keep representation, classification, and versioning claims separate and
   route them.
9. Record time, context, and persistence of the relation.
10. Leave competing metaphysical accounts visible rather than selecting one.
11. Route any observed sign that is used as evidence to the claim and evidence
    owner.

## Reference Delta

| Reference form | Typical contribution | Lexicon candidate delta |
|---|---|---|
| Dictionary | separates instance, realization, embodiment, and manifestation | joins them by direction and criterion, and names the excluded senses |
| Metaphysics reference | debates types, universals, and particulars | records the criterion in use without settling the debate |
| Philosophy of mind | supplies multiple realizability and functional kinds | keeps realization distinct from representation |
| Dispositions literature | supplies manifestation conditions | preserves the unmanifested disposition |
| Phenomenology and embodied cognition | supply the lived and constituting body | bounds embodiment to the bearer question |
| Bibliographic standard | defines work, expression, manifestation, and item | routes that chain to a mapping view instead of a sense |
| Clinical reference | defines signs and presentations | refuses symptom-to-diagnosis inference |

## Failure signs

- an instantiation is asserted with no stated criterion;
- instantiation and classification are treated as the same relation;
- realization and representation are merged;
- multiple realization is collapsed into equivalence;
- a disposition is treated as absent because it is not displayed;
- the word manifestation is used with no sense check, or the bibliographic
  sense is imported as a general one;
- an observed sign is read as establishing an underlying condition;
- embodiment is used to smuggle in a mind-body position;
- an avatar or persona is described as an embodiment of an agent;
- becoming concrete is recorded as a state transition;
- a language or runtime type, value, or function is recorded as a
  `general-type` or as a token instead of routed to the software entry;
- one metaphysical account is presented as settled.
