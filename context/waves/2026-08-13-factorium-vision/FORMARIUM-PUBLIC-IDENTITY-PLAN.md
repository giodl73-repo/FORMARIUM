# Formarium Public Identity Plan

Date: 2026-08-19
Status: active owner-authorized feedback rename

## Frame

Working canonical reference and two-book site
+ a public name that separates the collection from the proposed Formography method
-> a reversible Formarium feedback identity without rewriting stable source custody

Readers need one memorable name for the reference, its primary Tables book,
and its teaching companion. The owner has selected **Formarium** for live
feedback. The rename is a product decision, not evidence that Formography is a
novel or established field.

## Public identity

- project and repository: **Formarium**;
- primary book: **Formarium Tables**;
- teaching companion: **The Formarium Reader**;
- supporting software, if later admitted: **Formarium Workbench**;
- proposed research method: **Formography**.

## Compatibility boundary

Retain without migration:

- `.factorium` file extensions;
- `factorium-*` schema and command identifiers;
- canonical entry, view, relation, assurance, and edition identities;
- source paths and digest custody;
- historical `sim-01` through `sim-64` outputs and decisions.

The local checkout and GitHub repository may be renamed because those are
operator and discovery surfaces, not canonical content identities.

## Audit and comparison

`sim-51` already proves a reversible public-name overlay while preserving
canonical identities. `sim-64` is the current content fixed point. The
smallest implementation is therefore `sim-65`, inheriting `sim-64` exactly and
changing only public identity and feedback disclosure.

Formarium has public namespace collisions, including an apparent Swiss IT
company, an education-oriented use, a public GitHub project, and hobbyist use
for ant habitats. This work makes no uniqueness, trademark, domain,
availability, or market-distinctiveness claim. A formal clearance remains
required before commercial lock-in.

## Slice

1. add `sim-65` over the unchanged `sim-64` content and pointer registry;
2. render Formarium across home, Tables, Reader, chapters, entries,
   Composition, Pointer Entries, and handoff chrome;
3. expose the compatibility boundary on every generated page;
4. add static and 390-pixel browser checks;
5. update current product and two-book documentation;
6. rename the GitHub repository and local checkout only after validation.

## Stop and falsifier

Stop after the renamed repository, checkout, docs, and deterministic feedback
edition are validated. Do not migrate canonical identifiers or claim reader
preference. Reconsider the name if external readers confuse Formarium with
Formography, cannot identify the two books, or repeatedly associate it with an
existing organization or unrelated product.
