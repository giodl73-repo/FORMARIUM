# Scenario Evidence, Confidence, and Applicability Table

Status: candidate Evidence Table

Primary family: Evidence Table

Canonical headword: [Assumption, Condition, Scenario, Case, and Feasibility](../entries/scenario-assumption-condition-case.md)

Canonical senses: `assumption`, `condition`, `scenario`, `case`, `feasibility`

## Governing question

What supports the scenario frame and its application to this case, and which
assumptions, uncertainties, dependencies, or target differences remain open?

## Evidence table

| Element | Required evidence binding | Mandatory limitation |
|---|---|---|
| case | exact subject/configuration, boundary, version, time, owner | label similarity is not identity |
| assumption | proposition, purpose, source/rationale, alternatives, sensitivity, owner | not observed because accepted |
| condition | value/state/rule/event, method/source, time, uncertainty, dependence | may change or interact |
| scenario | inclusion rule, coherent conditions/developments, model, version, coverage | not prediction or probability by default |
| comparison | benchmark/control/counterfactual identity, frame mapping, adjustment, loss | no automatic causal effect |
| requirement/gate | authority, applicability, version, criterion, evidence | passage is rule-scoped |
| resource/dependency | identity, quantity/capacity, timing, compatibility, availability evidence | plan/commitment is not actual provision |
| feasibility result | exact frame, tests, unresolved items, sensitivity, reviewer, disposition | conditional, not achieved outcome |

## Confidence record

Confidence here is a bounded statement about support for an exact proposition
or result. It records proposition, basis, evidence quality, uncertainty,
dependencies, dissent, calibration if applicable, and revision trigger. A
verbal or numeric confidence label does not replace those bindings.

## Applicability procedure

1. Separate observed, measured, asserted, assumed, inferred, simulated,
   derived, and unresolved elements.
2. Compare source and target cases across population, boundary, context, time,
   mechanism, resource, dependency, and authority.
3. Record every adjustment, retained correspondence, relevant difference,
   uncertainty, and unmapped case.
4. Test the feasibility result under credible alternate assumptions and
   resource/dependency states.
5. State the supported claim and prohibited generalizations.
