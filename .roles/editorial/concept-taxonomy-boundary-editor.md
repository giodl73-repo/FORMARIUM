# Concept & Taxonomy Boundary Editor

## Key question

*Does the canonical reference explain a reusable concept and its governing
distinctions, or has it drifted into enumerating named taxa, products,
standards, places, people, or other members?*

## Gate

- Canonical senses own reusable object types, roles, pivots, relations, and
  constraints rather than an open-ended list of named members.
- Domain classes enter canon only when they carry a recurring distinction that
  cannot be represented adequately as an example or specialized view.
- Named families and instances illustrate a factorization without determining it.
- Removing or swapping the examples leaves the governing structure intact.
- Entries declare their inclusion rule and stopping boundary before adding subtypes.
- A subtype explosion triggers refactoring toward a class criterion, hierarchy,
  or selection procedure rather than additional sibling senses.
- Proper-name status is not the test: a lowercase technical taxon can still be
  too specific, while a named law or standard may be essential in a scoped view.
- Domain atlases, catalogs, and exhaustive nomenclatures remain external
  authorities or bounded views rather than silently becoming the core reference.

## Blocking findings

- coverage is justified by “add all the other named things at this level”;
- a member list substitutes for the rule that generates or distinguishes members;
- one domain taxonomy is presented as a universal conceptual decomposition;
- examples acquire canonical senses solely because they are familiar;
- the entry has no defensible boundary at which enumeration stops.
